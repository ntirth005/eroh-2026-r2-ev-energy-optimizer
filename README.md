# Engineers' Ring of Honour 2026 · Round 2 — AI energy framework for an EV charging and battery-swapping network

Case study (Naukri Campus, Engineers' Ring of Honour 2026, Round 2): an operator of public DC fast-charging hubs and battery-swap stations in five Indian metros (Delhi NCR, Mumbai MMR, Bengaluru, Hyderabad, Chennai; 1,200 MW, 600 MWh storage, 35 % renewable energy) wants to raise service reliability to about 90 %, cut storage and conversion losses to 8 % and keep EBITDA margins above 12 % in every cluster, in INR within the IEX market.

This repository is a **digital twin + decision framework**: probabilistic forecasting, day-ahead stochastic bidding and pricing, real-time storage MPC, simulated on 5 years of hourly data.

## Framework

```
Data → ① Forecast (LightGBM, hierarchical reconciliation, error scenarios)
     → ② Day-ahead decision (stochastic LP, CVaR): prices, hub-steering incentive, IEX bid, DISCOM schedule
     → ③ Real-time dispatch (hourly 6 h MPC): batteries, swap-rack charging, balancing purchases
     → ④ Execution + feedback
```

## Headline results (real IEX prices + real ERA5 weather, test year 23 Nov 2025 – 22 Nov 2026)

| KPI | Target | Incumbent (calibrated) | Full AI framework |
|---|---|---|---|
| Service reliability | ≈ 89.7 % | 77.8 % | **91.0 %** |
| Storage and conversion losses | 8 % | 9.9 % | **7.8 %** |
| EBITDA margin (network / weakest cluster) | > 12 % | 9.3 % / 6.0 % | **18.8 % / 13.7 %** |
| Network EBITDA | – | ₹338 Cr | **₹824 Cr** |

Reliability depends on an assumed driver response to the steering incentive (break-even ≈ 62 % of maximum); the loss target needs SiC chargers. See `results/` and the report for the ladder, stress tests, sensitivities and the synthetic-vs-real comparison.

> **Data caveat.** IEX prices and ERA5 weather are real. Charging/swap demand, customer price logs and battery state-of-health records are synthetic, and the incumbent baseline is calibrated to the case's stated KPIs.

## Get the data

```bash
python scripts/download_iex_dam.py        # opens Chromium, downloads IEX DAM hourly data in 30-day chunks -> data/iex_dam_5yr_hourly.csv
python scripts/download_era5_weather.py   # ERA5 weather for the 5 cities -> data/era5_<CITY>.csv
```
Downloads go to `data/` (raw IEX chunks to `data/raw/iex_chunks/`). Details in `data/README.md`.

## Data availability and sources

Both real data sets are free and public; raw files are **not** in this repository (the scripts above fetch them). Demand, customer price logs and battery records are synthetic and generated by the code; `DATA_MODE=synthetic` needs no downloads. Check each provider's terms before redistributing raw files.

- IEX India, Day-Ahead Market → Market Snapshot (hourly): https://www.iexindia.com/market-data/day-ahead-market/market-snapshot
- Open-Meteo Historical Weather API (ERA5): https://open-meteo.com/en/docs/historical-weather-api — licence CC BY 4.0: https://open-meteo.com/en/license
- Hersbach et al. (2020), *The ERA5 global reanalysis*, Q. J. R. Meteorol. Soc. 146, 1999–2049: https://doi.org/10.1002/qj.3803
- Hersbach et al., *ERA5 hourly data on single levels from 1940 to present*, Copernicus C3S Climate Data Store: https://doi.org/10.24381/cds.adbb2d47 (contains modified Copernicus Climate Change Service information)

## Run

```bash
./run_pipeline.sh real        # degradation fit → baseline calibration → forecasts → 270 simulations → tables/charts
./run_pipeline.sh synthetic   # same, with fully synthetic weather and price (no downloads needed)
python src/compare.py         # side-by-side synthetic vs real (after running both and copying out/ to results/<mode>/)
```
`run_all.py` uses every CPU core (about 14 minutes for 270 simulations on 12 cores). Outputs are written to `out/tables` and `out/charts`.

## What is modelled

Weather-driven renewable output and cluster demand; hub- and station-level overflow (queues and stock-outs); stationary-battery and swap-rack storage with fitted degradation and heat effects; grid-connection and DISCOM balancing limits; 5 % reserve; price elasticity with recapture inside the ±20 % tariff band; a paid hub-steering incentive; IEX bidding with scenario-based risk (CVaR); real-time MPC. All assumptions are in `src/params.py`.
